0
Skill trigger & mode detection Agent reads SKILL.md

The user sends a message containing a YouTube URL (or a summarization request). Claude has the distillery skill loaded at ~/.claude/skills/distillery/SKILL.md. It detects the trigger, counts the number of URLs, and routes to single-video or batch mode.

📄 SKILL.md lines 1–27 → video_id, mode (single | batch)
The SKILL.md file installed at ~/.claude/skills/distillery/SKILL.md is the agent's instruction set. Claude reads and executes it declaratively — there is no framework runner; Claude is the runtime.
1
Extract video ID Agent orchestration

Claude applies URL-parsing rules from SKILL.md to extract the 11-character video ID from any supported YouTube URL format. It then checks the local report directory for an existing distillation to avoid re-processing.

📄 SKILL.md lines 29–55 🔧 video_id.py → from_url() $ ls ~/Downloads/distillery/reports/*VIDEO_ID*.html → VIDEO_ID (11-char string)
Supported URL patterns (parsed by agent)
▸ youtube.com/watch?v=— standard watch URL
▸ youtu.be/{id}— short URL
▸ youtube.com/embed/{id}— embed URL
▸ youtube.com/live/{id}— live stream URL
▸ {11-char-id}— bare ID
2
Fetch video data Python subprocess

Claude runs ingest.py as a subprocess. This orchestrator launches two child subprocesses in sequence — one for the transcript, one for enriched metadata — then merges their outputs into a single JSON object that Claude parses for the next step.

📄 SKILL.md lines 58–99 🔧 ingest.py → ingest() → merged JSON (transcript + metadata)
Subprocess call chain inside ingest.py
1▸ fetch_transcript.py VIDEO_ID LANG_PREF
  → YouTubeTranscriptApi().list(video_id) (youtube-transcript-api)

3▸ ingest.py merges results — yt-dlp wins on channel/published/views/duration

⬇ AI AGENT ENTERS — content extraction begins
3
Canonical content extraction Claude AI — LLM inference

This is the only step where LLM inference runs. Claude reads the full timestamped transcript (plus optional description and chapters), then synthesizes a structured JSON document called the Canonical Extraction. No tools are called during this step — Claude produces the output as a raw JSON code block.

📄 SKILL.md lines 101–195 ✦ Claude reads transcript → produces Canonical JSON → Canonical Extraction (schema v1)
✦ What Claude produces in this step
  • summary — 2–4 sentence TL;DR of the video
  • takeaway — 1–3 sentence non-obvious insight beyond summary
  • keyPoints — 3–8 items: major claims, analytical depth, exact speaker quotes
  • outline — 5–20 timestamped topics with detail sentences
  • tags — 3–5 broad genre tags (ai, cloud, hardware…)
  • keywords — searchable headlines from keyPoints
  • Written entirely in the video's original language — never translated
Canonical Extraction schema (canonical.py)
{
  "schemaVersion": 1,
  "videoId": "dQw4w9WgXcQ",
  "summary": "2-4 sentence TL;DR...",
  "takeaway": "Non-obvious insight...",
  "keyPoints": [
    { "headline": "Core claim", "body": "...", "speakerQuote": "exact phrase" }
  ],
  "outline": [
    { "startSeconds": 0, "title": "Topic", "detail": "One sentence..." }
  ],
  "tags": ["ai", "developer"],
  "keywords": ["Key Term 1"],
  "filename": "2026-03-06-210126-distillery_dQw4w9WgXcQ_slug.html",
  // ... + title, channel, duration, publishDate, descriptionHtml, langWarn, transcript
}
⬆ AI AGENT EXITS — structured JSON handed off to renderer
4
Render HTML report Python subprocess Template substitution

Claude constructs the Canonical JSON inline as a Python heredoc, pipes it to render_report.py, which loads template.html, converts every field to HTML fragments, and performs string substitution. No LLM involved.

📄 SKILL.md lines 197–250 🔧 render_report.py → render() 🔧 render_report.py → canonical_to_template_keys() 🔧 render_fragments.py → key_points_to_html(), outline_to_html(), meta_line(), description_section() 🔧 canonical.py → validate(), build(), write_sidecar() 📄 template.html ({{PLACEHOLDER}} substitution) → ~/Downloads/distillery/reports/{filename}.html → ~/Downloads/distillery/reports/{filename}.json (sidecar)
Render pipeline inside render_report.py
1▸ Detect input format: if "schemaVersion" in data → Canonical path (line 132)
2▸ canonical_to_template_keys(extraction) — maps schema fields to {{UPPERCASE}} keys (lines 83–115)
3▸ HTML fragment generation via render_fragments.py:
  • key_points_to_html() — builds <li> list with headlines, bodies, quotes
  • outline_to_html() — timestamp links (?t=N), display as HH:MM:SS
  • meta_line() — "Channel · Duration · Date · Views"
  • description_section() — collapsible <details> block
4▸ template.read_text() → loop: html.replace("{{KEY}}", value) for all keys (lines 145–147)
5▸ Write HTML to ~/Downloads/distillery/reports/{filename}.html; write sidecar .json via canonical.write_sidecar()
Template placeholders in template.html
{{VIDEO_ID}} — 11-char YouTube ID
{{VIDEO_TITLE}} — page <title> and H1
{{VIDEO_URL}} — full watch URL
{{META_LINE}} — "Channel · Duration · Date · Views"
{{SUMMARY}} — TL;DR (escaped HTML)
{{TAKEAWAY}} — key insight (escaped HTML)
{{KEY_POINTS}} — pre-built <li> HTML
{{OUTLINE}} — pre-built <li> HTML with ts links
{{DESCRIPTION_SECTION}} — collapsible <details>
{{VIDEO_LENS_META}} — JSON for <script>
{{TRANSCRIPT}} — full transcript (escaped)
5
Serve & open in browser Shell script

Claude calls serve_report.sh with the HTML path. The script manages a single persistent HTTP server per user, kills any previous instance, starts a new one on port 8765, then opens the report URL in the default browser.

📄 SKILL.md lines 252–260 $ serve_report.sh OUTPUT_PATH 🔧 serve_report.sh — PID management, python3 -m http.server 8765 → http://localhost:8765/reports/{filename}.html (opens in browser)
serve_report.sh flow (80 lines)
1▸ Determine serve root — parent of reports/ dir, or file's own dir
2▸ Kill previous server: read ~/.cache/distillery/server.pid → kill $PID
3▸ Start server: python3 -m http.server 8765 --directory "$SERVE_DIR" & → save new PID
4▸ Open: open "http://localhost:8765/{URL_PATH}" (macOS) / xdg-open (Linux)
5▸ Print HTML_REPORT: $HTML_PATH for agent to parse
6
Update Knowledge Base Python subprocess Filesystem write

Claude calls knowledge_base.py store with the sidecar JSON path. The manifest is updated incrementally (add/update one report entry), then the gallery index.html is regenerated with the inlined manifest. Non-fatal — failure prints a warning and does not stop the pipeline.

📄 SKILL.md lines 262–272 🔧 knowledge_base.py → store() → ~/Downloads/distillery/manifest.json (updated) → ~/Downloads/distillery/index.html (regenerated)

Where the AI Agent Steps In and Out
⬇ Entry 1 — Pipeline controller (Steps 0–2, 4–6)

Claude acts as an orchestrator throughout. It parses the user's message, extracts the video ID, constructs and runs shell commands (ingest.py, render_report.py, serve_report.sh, knowledge_base.py), and interprets their JSON output. This is tool use / shell execution, not LLM inference. Claude is directing the flow, not generating content.

✦ Core AI Work — Step 3: Canonical Extraction

This is the sole LLM inference step. Claude receives the full timestamped transcript (and optional description/chapters) and synthesizes the Canonical Extraction JSON entirely from its language understanding. It produces: summary, takeaway, key points with analytical depth, a timestamped outline, and searchable tags/keywords. It writes in the video's original language without translating.

Input: transcript string (from ingest.py output, SKILL.md Step 2 stored variables)
Output: raw JSON code block (no prose) matching canonical.py schema v1

⬆ Exit 1 — After Step 3, before Step 4

After producing the Canonical JSON, Claude switches back to orchestrator mode. It constructs a Python heredoc containing the JSON, pipes it to render_report.py, and then calls serve_report.sh and knowledge_base.py — all shell/subprocess operations with no LLM involvement.

✦ Batch AI Work — Step B3: Cross-video Synthesis

A second LLM inference step that only runs in batch mode (2+ related videos). Claude receives all N transcripts simultaneously and generates the Synthesis JSON: shared themes, divergences, and a cross-video takeaway. Output is passed to batch.py for rendering.
